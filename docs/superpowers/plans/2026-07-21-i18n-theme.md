# i18n (pt-BR / en) + Theme Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship full TrainFlow web UI in Portuguese (Brazil) and English, plus light/dark/system theme, with toggles in the app shell.

**Architecture:** Cookie-based locale (`NEXT_LOCALE`, default `pt-BR`) via `next-intl` without URL prefixes. Theme via `next-themes` (`class` on `<html>`, default `system`). Message catalogs in `apps/web/messages/{pt-BR,en}.json`. Compose locale handling with existing Clerk middleware without redirect loops. Tailwind `darkMode: "class"` + paired `dark:` styles on shells and shared UI.

**Tech Stack:** Next.js 14 App Router, `next-intl`, `next-themes`, Tailwind CSS, Clerk (`@clerk/nextjs`)

## Global Constraints

- Locales: exactly `pt-BR` and `en`; default locale `pt-BR`.
- Theme modes: `light` | `dark` | `system`; default `system`.
- No URL locale prefixes (`/clients` stays `/clients`).
- Do not break Clerk middleware / cookie recovery / webhook public routes.
- Do not translate Clerk-hosted Account Portal or Excel/PDF file cell strings in v1 (UI chrome around export yes).
- Prefer existing zinc palette + `dark:` variants; no purple glow / generic AI aesthetic.
- Do not commit unless the user explicitly asks (TrainFlow session preference).

// apps/web/src/i18n/config.ts
export const locales = ["pt-BR", "en"] as const;
export type AppLocale = (typeof locales)[number];
export const defaultLocale: AppLocale = "pt-BR";
export const LOCALE_COOKIE = "NEXT_LOCALE";

export function isAppLocale(value: string): value is AppLocale {
  return (locales as readonly string[]).includes(value);
}
