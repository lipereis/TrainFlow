# TrainFlow mobile app shell (iOS + Android)

**Date:** 2026-08-07
**Scope:** New `apps/mobile` package in the monorepo. No changes to `apps/web`, Prisma, Clerk, or any existing backend logic.

## Context

TrainFlow currently exists only as a Next.js web app (`apps/web`), deployed to Vercel at `https://trainflow-chi.vercel.app`. The user wants a listing on both the Apple App Store and Google Play.

## Decisions made during brainstorming

- **Approach: wrap the existing web app, don't rewrite it.** Of the four options presented (Capacitor wrapper, React Native rewrite, fully native Swift+Kotlin, PWA-only), the user picked the Capacitor wrapper — fastest path to both stores, reuses 100% of the existing product including this session's landing-page redesign, at the cost of the app being a native shell around a WebView rather than a from-scratch native UI.
- **Points at the live production URL, not a static bundle.** TrainFlow is a full server-rendered app (Server Components, API routes, Prisma-backed data, Clerk auth) — it cannot be exported as static assets and bundled offline. Capacitor's `server.url` config loads `https://trainflow-chi.vercel.app` directly in the native WebView on both platforms. Consequence: the phone needs network connectivity to use the app (same as any account-based SaaS), and every future deploy to that URL updates the app instantly with no app-store re-submission needed for web-only changes.
- **Identity:** app name `TrainFlow`, bundle/package ID `com.trainflow.app` on both platforms (the user deferred to my recommendation — standard reverse-domain convention matching the product name). This ID cannot change after first store submission on either platform, so it's locked in now.
- **Icon:** the only existing brand asset (`apps/web/public/favicon.png`) is 260×260px, transparent background — too small for App Store (requires exactly 1024×1024, no alpha) and Play Store (512×512). The user chose to have it regenerated at full resolution from the same kettlebell mark design rather than supply new files themselves.
- **No native-specific features in this pass.** No push notifications, no native plugins (camera, biometrics, etc.), no offline mode. Pure web-wrapper — YAGNI holds until there's a concrete need for something a WebView can't do.
- **Environment constraint, disclosed and accepted:** this build environment is Windows with no Xcode and no Android SDK/Android Studio installed. I can scaffold both platform projects (`ios/`, `android/`) and validate config correctness (`npx cap doctor`), but cannot compile, launch a simulator/emulator, or run either app end-to-end from here. The user will open `ios/App.xcworkspace` in Xcode (needs a Mac) and `android/` in Android Studio themselves to build, test, sign, and submit. Store accounts (Apple Developer $99/yr, Google Play Console $25 one-time) are the user's responsibility to set up before the actual submission step — not required for scaffolding.

## Architecture

`apps/mobile/` — new pnpm workspace member, added to `pnpm-workspace.yaml`.

- `capacitor.config.ts` — `appId: "com.trainflow.app"`, `appName: "TrainFlow"`, `server: { url: "https://trainflow-chi.vercel.app", cleartext: false }`, `android: { allowMixedContent: false }`.
- `package.json` — `@capacitor/core`, `@capacitor/cli`, `@capacitor/ios`, `@capacitor/android`, `@capacitor/assets` (dev dependency, used once to generate icon/splash sets). No web framework dependencies — this package has no UI code of its own.
- `www/` — a minimal static placeholder directory (a single `index.html`). Required by Capacitor's CLI tooling even in remote-`server.url` mode (it's never actually shown to users since `server.url` takes over at runtime), and is also where `@capacitor/assets` reads the source icon from during generation.
- `resources/icon.png` (1024×1024, solid background) and `resources/icon-foreground.png` (Android adaptive icon foreground layer) — regenerated kettlebell mark, sourced from the same design as `apps/web/public/favicon.png` but redrawn at full resolution with a solid background since the original has transparency Apple's icon spec forbids.
- `resources/splash.png` (2732×2732, centered mark on solid background) — generated once, `@capacitor/assets` derives every platform-specific splash size from it.
- `ios/` — generated by `npx cap add ios`. Xcode project + workspace. Icon/splash wired in via `npx cap sync ios` after `@capacitor/assets` runs. User builds/signs/submits from Xcode on a Mac.
- `android/` — generated by `npx cap add android`. Gradle project. Icon/splash wired in via `npx cap sync android`. User builds/signs/submits from Android Studio.

## What does not change

- `apps/web` — zero code changes. The mobile shell is purely additive and points at the already-deployed production URL.
- Auth: Clerk's web sign-in flow runs as-is inside the WebView (cookies work normally in a real browser engine) — no native Clerk SDK integration needed for this pass.
- No new backend endpoints, no push notification infra, no deep linking configuration.

## Testing / verification

What I can verify from this environment:
- `capacitor.config.ts` is syntactically valid and matches the values above.
- `npx cap doctor` reports the project structure as valid for both platforms.
- Generated `ios/` and `android/` directories exist with the expected Capacitor-generated structure (Xcode project files, Gradle files).
- Icon/splash source files exist at the correct dimensions and `@capacitor/assets` completes without error, confirming it wrote the full per-platform asset set.

What requires the user's own machine:
- Actually building, running in a simulator/emulator or on a physical device, code-signing, and submitting to either store.
