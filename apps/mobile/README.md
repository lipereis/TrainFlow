# TrainFlow mobile app shell

Capacitor wrapper around the production deployment (`https://trainflow-chi.vercel.app`). No native code — this is a WebView shell, so any change to the live site appears in the app immediately with no rebuild needed.

## First-time setup (required after any fresh clone)

The native `ios/` and `android/` projects reference generated files (`capacitor.config.json`, the `public/` web assets folder, and — for Android — a path under `node_modules`) that are gitignored and not committed. Before opening either project, run from the repo root:

```bash
pnpm install
cd apps/mobile
npx cap sync
```

Re-run `npx cap sync` any time you change `capacitor.config.ts`, or after a fresh clone/checkout, or after bumping the Capacitor version (the Android `capacitor.settings.gradle` file embeds the exact resolved `@capacitor/android` version in its path and is regenerated by `cap sync` — never hand-edit it, its own header says so).

## What's here

- `capacitor.config.ts` — app identity (`com.trainflow.app` / "TrainFlow") and the remote URL it loads
- `ios/` — Xcode project. Open `ios/App/App.xcodeproj` in Xcode on a Mac.
- `android/` — Gradle project. Open `android/` in Android Studio.
- `assets/logo.png` — source icon (1536×1536, transparent) used to generate all icon/splash sizes

## To build and submit

**iOS** (requires a Mac with Xcode):
1. Open `apps/mobile/ios/App/App.xcodeproj` in Xcode (this project uses Swift Package Manager, not CocoaPods — no `pod install` step needed; Xcode resolves the Swift package automatically on first open)
2. Set your Apple Developer team under Signing & Capabilities
3. Product → Archive, then follow Xcode's App Store Connect submission flow
4. Requires an active Apple Developer Program membership ($99/yr)

**Android** (requires Android Studio):
1. Open `apps/mobile/android` in Android Studio and let it sync
2. Build → Generate Signed Bundle/APK
3. Upload the resulting `.aab` to Google Play Console
4. Requires a Google Play Console account ($25 one-time)

Both platforms track their own build/version numbers, and neither store accepts a re-upload at the same number: `android/app/build.gradle` (`versionCode`/`versionName`) and the iOS project (`CURRENT_PROJECT_VERSION`/`MARKETING_VERSION`) all start at `1`/`1.0`. Bump them before each new store submission — worth remembering since this shell rarely needs resubmission (web-only changes to the live site need none at all, since the WebView just loads whatever's live).

## Known App Store review risks (iOS only)

This app is a thin WebView wrapper with no native functionality beyond loading the production site, which risks rejection under **Guideline 4.2 (Minimum Functionality)** — Apple commonly rejects wrapper apps that don't do meaningfully more than a website. Separately, billing goes through Stripe's hosted checkout for a digital subscription consumed inside the app, which risks rejection under **Guideline 3.1.1 (In-App Purchase)** — Apple generally requires In-App Purchase (not an external payment processor) for digital subscriptions used within the app. Neither risk has been mitigated here; both are worth reviewing against current App Store guidelines before submitting. Google Play has no equivalent requirement for either, so the Android build isn't affected.

Also verify whether social sign-in (e.g. Google) is enabled in the Clerk dashboard, and if so, test that it actually works inside the app's WebView before submitting. Google (and some other OAuth providers) block sign-in inside embedded WebViews with a `403 disallowed_useragent` error; the usual fix (routing OAuth through the system browser) requires a native plugin, which is out of scope for this shell. It may need to be disabled for mobile or reworked later if it doesn't work.

## Regenerating icons

If the brand mark changes, replace `assets/logo.png` (keep it square, at least 1024×1024, with transparency) and re-run from `apps/mobile`:

```bash
npx capacitor-assets generate --ios --android --iconBackgroundColor "#0c0e0d" --iconBackgroundColorDark "#0c0e0d" --splashBackgroundColor "#0c0e0d" --splashBackgroundColorDark "#0c0e0d"
npx cap sync
```

`assets/logo.png` is transparent and only generates app icons/splash screens. It doesn't cover store listing assets: Play Console additionally needs a 512×512 listing icon and a 1024×500 feature graphic, and App Store Connect needs screenshots. Neither is produced by this pipeline — prepare them separately before submitting.
